## 1. 팔레트 — 왜 파일 하나만 고치면 되는가

> **비유.** 앱의 색은 **페인트 통 목록**으로 관리된다.
> 벽마다 직접 색을 칠해 둔 게 아니라, 벽에 **"여기는 3번 통"** 이라고 이름표만 붙여 놨다.
> 그래서 **3번 통의 내용물만 갈아 끼우면** 그 이름표가 붙은 벽이 전부 한꺼번에 바뀐다.

그 페인트 통 목록이 `src/constants/theme.ts`의 `Colors.light`다.
실제로 확인해 보니 **`theme.ts` 밖에서 색을 직접 쓴 곳이 0건**이었다 —
hex도, `rgba()`도, `"white"` 같은 이름도 없다. 이름표만 붙어 있다는 뜻이고,
그래서 파일 하나로 앱 전체 색이 바뀐다.

### 바꾼 값

| 토큰 | 이전 | 이후 |
|---|---|---|
| `text` | `#10233A` | `#1B2B3D` |
| `background` | `#F6F9FD` | `#F7F9FB` |
| `textSecondary` | `#667484` | `#64748B` |
| `textMuted` | `#607489` | `#5E7186` |
| `border` / `borderSubtle` | `#E4EBF3` / `#EEF3F8` | `#E6EBF0` / `#F0F4F8` |
| `accent` | `#1668E3` | `#2C6BB8` |
| `accentTint` / `accentBorder` | `#EAF2FE` / `#CFE0F7` | `#EAF1F9` / `#CDDDF0` |
| `highlight` | `#F36C1C` | `#DA7333` |
| `positive` / `danger` / `chartMuted` | — | 그대로 |

그림자도 옅게: 카드 `0.08 → 0.05`, 파란 버튼 `0.35 → 0.2`.

### 얼마나 바뀌었나 — **"방을 다시 칠한 게 아니라 가구 두 개를 바꿨다"**

색이 얼마나 달라졌는지 재는 단위가 있다(ΔE). **2 미만이면 나란히 놓아야 겨우 보이는 차이**다.

| 토큰 | ΔE | 체감 |
|---|---|---|
| `accent` (파랑) | **27.9** | 완전히 다른 색 |
| `highlight` (주황) | **17.7** | 완전히 다른 색 |
| `text` | 5.4 | 분명히 다름 |
| 배경·카드·테두리 | 0.7~2.1 | **거의 그대로** |

즉 **벽과 바닥(배경·카드·테두리)은 손대지 않았고, 파랑과 주황만 갈았다.**
그런데 이 둘이 주 버튼·선택 상태·탭 표시·그래프 강조를 전부 차지해서
체감은 "같은 앱인데 톤이 가라앉았다" 쪽으로 크게 온다.

선택지 4개 중 **변화 폭이 가장 작은** 안이었다. 더 크게 바꾸려면 배경을 흰색 계열에서 떼야 한다.

## 2. "대비비 계약" — 꼭 지켜야 하나

> **비유.** 대비(contrast)는 **안개 속 글씨**다.
> 흐린 회색 글씨를 흰 종이에 쓰면 젊은 눈엔 읽히지만, **노안이 온 눈에는 안개 속이다.**
> `4.5:1`은 "안개가 이 정도까지는 걷혀야 한다"는 최소선이다.

`theme.ts` 주석에 규칙이 4개 박혀 있었는데, **성격이 다 다르다.**

| 규칙 | 정체 | 지켜야 하나 |
|---|---|---|
| 본문 **AA 4.5:1** | 국제 접근성 표준(WCAG) | **그렇다.** 이 앱 사용자가 고령이라 명목이 아니라 실질 |
| `accentTint` 위 글자 제한 | 위 규칙을 특정 면에 적용한 **파생** | 별개 규칙 아님 — 위를 지키면 자동 |
| `highlight` **3:1** | WCAG 1.4.11 (비텍스트 대비) | **그렇다.** 비용이 거의 없다 |
| `chartMuted` < `highlight` | **순수 디자인 의도** (주황이 먼저 읽히게) | 아니다. 취향 |

**특히 `textMuted`를 흐리게 두면 안 되는 이유**가 하나 더 있다.
「청력 검사·진단 결과가 아니에요」라는 **고지 문구**가 이 색으로 나온다.
안 읽히면 곤란한 문장이다.

**실제 트레이드오프는 하나뿐이다.** AA 때문에 못 하는 건 *"더 옅고 산뜻한 회색 글씨"* 다.
그 외 팔레트 자유도는 거의 제약받지 않았다.

## 3. 감사 — 앱이 **실제로** 지키고 있나

> **비유.** 페인트 통에 *"이 색은 흰 벽에만 쓸 것"* 이라는 **라벨**을 붙여 놨다고 해서,
> 현장에서 그대로 지켰다는 보장은 없다. **현장을 돌며 눈으로 확인**한 것이 이 감사다.

**결론: 두 규칙 다 지키고 있다. 위반 0건.**

글자가 올라가는 면은 앱 전체에서 **딱 4개**뿐이었고, 각 면의 글자색을 전수 확인했다.

| 면 | 올라가는 글자색 | 대비 |
|---|---|---|
| 흰 카드 `surface` | text / textSecondary / textMuted / accent / positive / danger | 4.56~14.39 |
| 배경 `background` | 위와 같음 | 4.51~13.63 |
| 파란 버튼 `accent` | `onAccent`(흰색)만 | 5.38 |
| 옅은 파란 타일 `accentTint` | **`accent` 또는 `text`만** | 4.73 / 12.64 |

`accentTint` 사용처 **19곳 전부** 열어봤다. 대부분은 **타일 안엔 아이콘만 넣고,
흐린 글자는 타일 바깥 흰 면에 두는** 구조라 애초에 문제가 생길 수 없다.

의식적으로 지킨 흔적도 있다 — 코드에 규칙이 주석으로 박혀 있다.

```

WrsBingoScreen.tsx:781     accentTint 위 글자는 text·accent만 AA. textMuted는 미달.
```

`highlight`(주황)는 `color:`로 쓰인 곳이 **0건**이다. 그래프 점·막대·컨페티 같은
**칠하는 용도로만** 쓴다 — 규칙대로다.

## 4. Jest — 무엇이고, 왜 안 돌았나

> **비유.** 테스트는 **자동 채점기**다.
> 이 앱에는 **238문항짜리 모의고사**가 이미 만들어져 있다.
> 코드를 고칠 때마다 그 시험을 30초 만에 다시 치러서, 뭘 깨뜨렸는지 알려 준다.
> 특히 **눈으로는 검증이 거의 불가능한 것**에 쓴다 —
> "정답 2번이면 난이도 한 칸 내리고, 오답 1번이면 두 칸 올린다" 같은 규칙을
> 손으로 확인하려면 수십 문항을 직접 풀어야 한다.

`__tests__` 폴더의 성격 자체는 `docs/testing-guide.md`에 이미 정리돼 있다. 여기선 **왜 안 돌았는지**만.

### 증상

```
> jest
'jest' is not recognized as an internal or external command
```

### 고장이 **2개** 겹쳐 있었다

> **비유 ①.** 프로그램은 하드디스크에 **설치돼 있는데 바탕화면 아이콘이 없는** 상태.
> 컴퓨터는 "그런 프로그램 없다"고 한다. 실제로 없는 게 아니라 **부르는 길이 없는** 것.

`node_modules/jest`(알맹이)는 있는데 `node_modules/.bin/jest`(바로가기)가 없었다.
같은 패키지가 만드는 바로가기 둘 중 `create-jest`만 있고 `jest`는 없는,
**설치가 중간에 끊긴** 전형적 흔적이었다.

> **비유 ②.** 채점기는 있는데 **답안지 판독기가 없는** 상태.
> 이 앱 코드는 채점기가 바로 못 읽는 형식(RN/Expo)이라 번역기가 필요하다.

그 번역기가 `jest-expo`인데 아예 안 깔려 있었다. 우회해서 직접 불러도 여기서 멈췄다.

```
● Validation Error: Preset jest-expo/android not found.
```

### 덤 — `tsc` 에러의 정체

> **비유.** `@types/jest`는 **사전**이다. 없으면 타입 검사기가 `expect`·`it` 같은 단어를 모른다.

`npx tsc --noEmit`에서 쏟아지던 `Cannot find name 'expect'`는
**코드가 틀린 게 아니라 사전이 안 깔린 것**이었다.

### 해결 — `npm install` 한 줄

`package.json`과 `package-lock.json`엔 필요한 게 전부 적혀 있었다. 빠진 것만 채우면 끝이었다.

```
Test Suites: 27 passed, 27 total
Tests:       238 passed, 238 total
Time:        31.368 s
```

`tsc` 에러도 **0건**이 됐다. 팔레트 변경이 깨뜨린 것도 없다.
