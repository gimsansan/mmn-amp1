# 화면 동작 지도 — 이 앱에 적용 (#1)

> **지침 원본**: 예전 `analaysys/ask-file-be.md`. 2026-08-24 삭제. 이 파일은 적용 결과만.
> **표기**: 화면은 `[이름]`, 전환은 `--동작-->`. 동그라미 숫자 안 씀.
> **범위**: 화면을 갈아끼우는 파일만. 저장·계산 파일은 다른 축 문서로.
> **날짜**: 2026-08-21 · `근거` = 파일을 읽고 확인한 것

---

## 0. 한 줄

**라우트는 4개뿐이고, 나머지 화면 전환은 전부 `useState` 한 개로 컴포넌트를 통째로 갈아끼운다.**

그래서 "이 앱에 화면이 몇 개냐"를 라우트 개수로 세면 틀린다. 실제로 사용자가 보는 화면은 20개쯤 되는데, 파일 시스템에는 4개만 있다.

---

## 1. 제일 바깥 — 탭 4개

```
[앱] --시작--> [_layout] --탭바--> [링 6] [소리 높낮이] [단어 듣기] [떨림]
```

`근거`: `src/app/_layout.tsx` → `components/app-tabs.tsx`의 `NativeTabs.Trigger` 4개.

| 탭 라벨 | 라우트 파일 | 실제 컴포넌트 |
|---------|------------|--------------|
| 링 6 | `src/app/ling6.tsx` | `Ling6SessionScreen` |
| 소리 높낮이 | `src/app/pta.tsx` | `PtaSessionScreen` |
| 단어 듣기 | `src/app/wrs.tsx` | `WrsTabScreen` |
| 떨림 | `src/app/index.tsx` | `AmTabScreen` |

**주의 — 헷갈리기 쉬운 곳 하나**: `index`는 홈이 아니라 **떨림 탭**이다. 라우트 이름과 라벨이 안 맞는 유일한 자리다.

라우트 파일 4개는 전부 3줄짜리다. `export default function Ling6Route() { return <Ling6SessionScreen /> }` 이게 전부다. 즉 **라우트 파일에는 로직이 없다.**

---

## 2. 탭 안 — 화면 갈아끼우기

여기가 이 앱의 핵심 구조다. 네 탭이 각자 다른 방식으로 화면을 바꾼다.

### 링 6 탭 — 탭이 곧 연습

```
[링 6 시작] --연습 시작--> [듣는 중] --소리 끝--> [고르기]
[고르기] --선택--> [맞았어요/아쉬워요] --다음--> [듣는 중]
[고르기] --8문항 끝--> [결과]
[결과] --다시 연습--> [듣는 중]
[링 6 시작] --헤더 차트--> [연습 기록]
[결과] --헤더 차트--> [연습 기록]
[연습 기록] --뒤로 가기--> [링 6 시작]
```

`근거`: `Ling6SessionScreen.tsx` — `phase` 상태 하나(`idle | playing | choose | feedback | summary`)가 위 다섯 화면을 결정하고, `showStats`가 통계로 갈아끼운다.

**볼 자리**: 파일 맨 위쪽의 `if (showStats) { return <StatsScreen ... /> }`. 이 조기 `return` 하나가 "화면 갈아끼움"의 전부다.

### 소리 높낮이 탭 — 두 연습 중 고름

```
[연습 고르기] --높낮이 비교--> [듣기 준비] --시작--> [높낮이 비교 연습]
[연습 고르기] --다른 음 찾기--> [듣기 준비] --시작--> [다른 음 찾기 연습]
[연습 고르기] --헤더 차트--> [연습 기록]
[듣기 준비] --뒤로--> [연습 고르기]
[높낮이 비교 연습] --뒤로--> [연습 고르기]
```

`근거`: `PtaSessionScreen.tsx` — `track` 상태(`"picker" | "pitch2" | "freq"`) + `checked`(듣기 준비 통과 여부).

**듣기 준비**(`ListeningCheckScreen`)는 소리가 제대로 나는지 먼저 확인시키는 칸이다. **첫 시작 전에 한 번만** 뜬다(`checked`가 true가 되면 다음부터 건너뜀).

### 단어 듣기 탭 — 세 연습 중 고름

```
[연습 고르기] --한 글자--> [한 글자 연습]
[연습 고르기] --두 글자--> [두 글자 연습]
[연습 고르기] --단어 빙고--> [빙고]
[연습 고르기] --(한국어 음성 없음)--> [음성 안내]
[음성 안내] --다시 확인--> [연습 고르기 또는 그 연습]
```

`근거`: `WrsTabScreen.tsx` — `track` 상태(`"picker" | "one" | "two" | "bingo" | "voiceGuide"`).

**특이한 갈래 하나**: 연습 카드를 누르면 바로 안 들어가고 `hasKoreanVoice()`를 먼저 물어본다. 한국어 TTS가 없으면 연습 대신 **[음성 안내]** 화면으로 샌다. 소리가 안 나는 채로 연습이 시작되면 찍기가 되기 때문이다(`근거`: `wrsTts.ts` 주석 — 실기기에서 확인).

**주의**: 이 탭의 [연습 고르기]에는 **헤더 차트 버튼이 없다.** 통계는 [한 글자]·[두 글자] 안에서만 열린다.

### 떨림 탭 — 링 6와 같은 꼴

```
[떨림 시작] --연습 시작--> [듣기 준비] --시작--> [듣는 중] --> [고르기] --> ...
[떨림 시작] --헤더 차트--> [연습 기록]
```

`근거`: `AmTabScreen.tsx` — `showStats` · `showCheck` 두 플래그로 세 화면을 갈아끼움.

## 3. 연습 화면 다섯 단계 (네 연습 공통)

한 글자·두 글자·링 6·떨림·높낮이 비교·다른 음 찾기가 **전부 같은 뼈대**다.

```
[시작] --연습 시작--> [듣는 중] --소리 끝--> [고르기]
[고르기] --답 선택--> [맞았어요/아쉬워요] --다음--> [듣는 중]
                                          └--마지막 문항--> [결과]
[결과] --다시 연습--> [듣는 중]
```

`근거`: 여섯 파일 모두 `type Phase = "idle" | "playing" | "choose" | "feedback" | "summary"`로 똑같이 선언돼 있다.

**이걸 알면 새 연습 화면을 읽을 때 20분이 2분이 된다.** 파일을 열면 `phase`부터 찾고, `phase === "..."` 분기 다섯 개만 훑으면 화면 그림이 끝난다.

빙고만 예외적으로 `[고르기]`가 판을 누르는 식이라 흐름이 조금 다르지만, `Phase` 이름은 같다.

---

## 4. 통계 화면 — 네 탭이 같은 화면으로 모임

```
[링 6 시작]   --헤더 차트--> [연습 기록]
[한 글자]     --헤더 차트--> [연습 기록]
[두 글자]     --헤더 차트--> [연습 기록]
[떨림 시작]   --헤더 차트--> [연습 기록]
[연습 고르기(음고)] --헤더 차트--> [연습 기록]
[연습 기록]   --칩 누름--> [연습 기록]   (화면은 그대로, 내용만 바뀜)
[연습 기록]   --뒤로 가기--> (열었던 화면)
```

`근거`: `StatsScreen.tsx` — 다섯 진입점이 전부 같은 컴포넌트를 `initialKind`만 다르게 부른다.

**「칩 누름」이 화살표가 아닌 이유**: 칩은 화면을 바꾸지 않는다. 같은 화면 안에서 그리는 종목만 바뀐다. 화면 축에서는 **이동 없음**으로 읽는 게 맞다.

---

## 5. 이 앱에서 「화면 갈아끼움」을 찾는 요령

지침 §2-1의 "볼 자리"(`if` / `switch(phase)` / 이른 `return`)를 이 앱에 맞춘 것:

| 찾을 것 | 뜻 |
|---------|-----|
| `if (showStats) return <...>` | 통계로 통째로 갈아끼움 |
| `if (track === "one") return <...>` | 탭 안에서 연습 고름 |
| `if (!checked) return <ListeningCheckScreen ...>` | 듣기 준비 게이트 |
| `{phase === "idle" ? ... : null}` | 한 화면 안에서 칸이 바뀜 |

**앞의 셋은 화면 전환, 마지막 하나는 같은 화면 안 표시 변화다.** 조기 `return`이면 화면이 바뀐 것, JSX 안 삼항이면 안 바뀐 것 — 이 구분이 이 앱에서 가장 쓸모 있다.

## 6. 안 그린 것 (일부러)

- 각 `onPress`가 하는 일 — 지침 §4대로 지도 한 장에 이미 이어져 있다
- `setState` 목록 — 상태 축(#3) 문서로
- 소리가 언제 나는지 — 화면 축이 아니다

## 7. 단정 금지

- `근거`: 위 화살표는 전부 파일을 읽고 확인했다(`Ling6SessionScreen` · `PtaSessionScreen` · `WrsTabScreen` · `AmTabScreen` · `StatsScreen` · `app-tabs.tsx`).
- `미검증`: 실기기에서 이 순서대로 눌러 본 것은 아니다. 코드상의 분기를 읽은 결과다.
- `주의`: 안드로이드 하드웨어 뒤로가기는 화면마다 `BackHandler`로 따로 붙어 있어, 위 화살표와 **다르게 동작할 수 있다**. 그 지도는 여기 안 그렸다.
