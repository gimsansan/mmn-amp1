# 7축 코드 분석 — 이 앱에 적용한 결과

> **무엇인가**: [`analaysys/`](../../analaysys/)의 **질문 요령 7개**를 이 앱의 주요 파일에 실제로 적용해 본 결과.
> **지침 vs 결과**: `analaysys/ask-*.md`는 **어떻게 물어보나**(범용, 어느 프로젝트에나 씀). 여기 `docs/analysis/ask-*.md`는 **그래서 이 앱은 어떤가**(이 저장소 전용).
> **파일명이 같은 이유**: 어느 지침을 적용한 결과인지 한눈에 맞추려고. 지침 하나 = 결과 하나.
> **성격**: 갱신형 — 코드가 바뀌면 그 자리를 고친다(과거 서술을 남기지 않는다).
> **작성**: 2026-08-21

## 읽는 순서

축은 **한 번에 하나씩** 본다. 동시에 다 보면 흐려진다(지침 공통 원칙).

| 순서 | 축 | 문서 | 한 줄 결론 |
|------|-----|------|-----------|
| 1 | 화면 | [`ask-file-be.md`](./ask-file-be.md) | 라우트는 4개뿐, 나머지 화면은 `useState`로 갈아끼운다 |
| 2 | 데이터 | [`ask-data-flow.md`](./ask-data-flow.md) | 서버가 없다. 저장소 4개가 전부 |
| 3 | 상태 | [`ask-state-management.md`](./ask-state-management.md) | 전역 상태가 하나도 없다 |
| 4 | 에러 | [`ask-error-handling.md`](./ask-error-handling.md) | 실패하는 자리는 셋 — 소리·저장소·TTS 음성 유무 |
| 5 | 타입 | [`ask-types-contracts.md`](./ask-types-contracts.md) | 「외부 데이터」가 어제 내 앱이 저장한 값이다 |
| 6 | 성능 | [`ask-performance.md`](./ask-performance.md) | 무거운 건 화면이 아니라 소리. **측정은 안 했다** |
| 7 | 테스트 | [`ask-testing.md`](./ask-testing.md) | 230개 중 210개가 순수 함수 단위 |

**처음이면 1 → 2 → 3 순서를 권한다.** 이 셋이면 앱 구조가 잡힌다. 4~6은 필요할 때, 7은 뭔가 고치기 직전에.

## 이 앱을 한 장으로

일곱 축에서 나온 것을 지침의 표기법으로 겹치면:

```
[탭 4개] --갈아끼움--> [연습 화면] --(phase)--> [듣는 중] → [고르기] → [결과]
                                                    │
                                          !소리 실패! --잡음--> [문구] --복구--> [고르기]
                                                    │
[결과] --요약 숫자만--> {저장소 4개}  (25문항 미완이면 저장소가 거부)
                            │
                            └--loadStatsFeed--> (feed)@[연습 기록] --칩--> 종목 하나만 그림
```

`[ ]` 화면 · `{ }` 데이터 · `( )@소유자` 상태 · `!` 실패

## 일곱 축을 관통하는 것 세 가지

축을 따로 그렸는데 같은 성질이 반복해서 나왔다. 이 앱을 이해하는 지름길이다.

**1. 화면을 믿지 않는다.**
저장소가 25문항 미완을 거부하고(#2·#4), 읽을 때 레코드를 검증하고(#5), 계산 함수가 잘못된 값에 예외를 던진다(#4). 화면은 여러 개고 늘어나지만 저장소는 하나라, 마지막 관문을 아래에 뒀다.

**2. 없는 값을 0으로 채우지 않는다.**
대표 숫자가 없으면 `null`이고, 그래프는 그 점만 뺀다(#2·#5). 기록이 1건이면 선을 안 그리고 "내일 또 하면 선이 생겨요"라고 쓴다. 0으로 채우면 **거짓 기록**이 되기 때문이다.

**3. 규모에 맞는 만큼만 한다.**
전역 상태 라이브러리 없음(#3), `useMemo` 0개(#3·#6), `FlatList` 없음(#6), E2E 없음(#7). 데이터가 50건 상한이고 목록이 열 개 미만이라 필요가 없다. **지금 규모에서 맞는 선택**이지 영원한 정답은 아니다.

## 유지 규칙

- 코드가 바뀌면 **해당 축 문서의 그 자리를 고친다** (갱신형)
- 새 축을 만들지 않는다 — 일곱 개가 `analaysys/`의 지침 수와 맞다
- `근거`(확인함) · `추정` · `미검증` · `주의` 표기를 계속 쓴다. 프로젝트 공통 규칙이다
