## 0. 한 줄

**전역 상태가 하나도 없다.** 지침 §2의 네 종류 중 **3(전역)은 이 앱에 없고**, 1(지역)·2(공유)·4(파생)만 쓴다.

Zustand도 Redux도 Context도 없다. 화면 하나가 자기 상태를 다 들고, 필요한 것만 자식에 내려준다.

`근거`: `createContext`를 쓰는 곳은 `_layout.tsx`의 `ThemeProvider` 하나뿐인데, 이건 expo-router가 요구하는 것이고 값도 고정(`DefaultTheme`)이다.

## 1. 색은 상태가 아니다 (먼저 짚을 것)

`useTheme()`가 훅처럼 생겨서 전역 상태로 오해하기 쉽다. **아니다.**

```ts
export function useTheme(): Record<ThemeColor, string> {
  return Colors.light;   // 끝. 상태도 구독도 없음
}
```

다크 모드를 구현하지 않기로 해서 **라이트 고정**이다. 훅 모양으로 남겨 둔 건 호출부 20여 곳을 안 고치려는 것뿐이다(`근거`: `use-theme.ts` 주석).

→ **이걸 바꿔도 다시 그려지는 것이 없다.** 성능 축에서도 무시해도 되는 자리다.

---

## 2. 지역 상태 — 연습 화면의 `phase`

이 앱에서 가장 중요한 상태 하나만 꼽으면 이것이다.

```
(phase)@각 연습 화면       "idle" | "playing" | "choose" | "feedback" | "summary"

[연습 시작 누름] --설정--> (phase) = "playing"
[소리 끝남]     --설정--> (phase) = "choose"
[보기 선택]     --설정--> (phase) = "feedback"
[다음 누름]     --설정--> (phase) = "playing"  (또는 마지막이면 "summary")
```

`근거`: 여섯 연습 화면이 전부 같은 `Phase` 유니온을 선언한다.

**이 값이 다른 화면에서 필요해질 여지가 있나?** — 없다. 연습이 끝나면 결과 숫자만 저장소로 나가고, `phase`는 화면과 함께 사라진다. **지역으로 충분하다.**

---

## 3. 공유 상태 — 탭이 들고 연습이 쓰는 것

지침 §2-2의 "누가 원본을 들고, 누가 읽고, 누가 바꾸나"가 이 앱에서 세 개 있다.

```
(mode)@AmTabScreen --initialMode--> [AmSessionScreen]
                   <--onModeChange--
```

| 상태 | 원본 소유자 | 왜 위에 있나 |
|------|------------|-------------|
| `(mode)` 귀풀기/연습 | 탭 화면 | **듣기 준비로 화면을 갈아끼워도 선택이 유지돼야** 함. 연습 화면이 들고 있으면 갈아끼울 때 사라진다 |
| `(checked)` 듣기 준비 통과 | 탭 화면 | 한 번 통과하면 그 탭에 있는 동안 다시 안 뜨게 |
| `(autoStart)` 준비 직후 자동 시작 | 탭 화면 | 준비 화면 → 연습 화면으로 갈아끼운 직후 바로 시작시키려고 |

**깊이는 한 단계다**(탭 → 연습 화면). prop drilling 걱정할 깊이가 아니다.

**`autoStart`가 이 앱에서 유일하게 까다로운 공유 상태다.** 한 번만 쓰이고 꺼져야 하므로, 쓴 쪽이 `onAutoStartConsumed()`로 되돌려 준다. 안 그러면 연습이 끝날 때마다 다시 자동 시작된다.

```
[듣기 준비 통과] --설정--> (autoStart)@탭 = true
[연습 화면이 소비] --onAutoStartConsumed--> (autoStart)@탭 = false
```

## 4. 파생 상태 — 전부 계산한다 (저장하지 않는다)

지침 §0 "이유 3"(파생값을 저장하면 낡는다)에 대해, 이 앱은 **저장을 아예 안 한다**.

```ts
const running = phase === "playing" || phase === "choose" || phase === "feedback";
const choiceDisabled = phase !== "choose";
const hasRecords = countOfKind(feed, kind) > 0;
```

전부 렌더 본문의 한 줄 계산이다. `(phase)` 하나만 원본이고 나머지는 여기서 나온다.

**`useMemo`가 코드베이스에 0개다.** (`근거`: `grep -rn "useMemo" src` → 0건)

이게 게으른 게 아니라 맞는 선택인 이유: 위 계산들은 **비교 한 번**이라 메모이제이션 비용이 계산 비용보다 크다. 지침 §4의 "값싼 계산에 `useMemo`는 과함"에 해당한다.

## 5. 이 앱의 특수 규칙 — `useState` vs `useRef`

여기가 이 앱을 읽을 때 가장 헷갈리는 자리다. 같은 값이 **둘 다** 있는 경우가 있다.

```ts
const markedRef = useRef<boolean[]>(emptyMarked());   // 비동기 콜백이 읽을 최신 값
const [marked, setMarked] = useState<boolean[]>(emptyMarked());  // 화면이 그릴 값
```
`근거`: `WrsBingoScreen.tsx:53,59`

**왜 둘인가:**

| | `useRef` | `useState` |
|---|---------|-----------|
| 바꾸면 다시 그리나 | 아니오 | 예 |
| 비동기 콜백에서 최신 값 읽히나 | 예 | **아니오** (그 시점 값에 갇힘) |

소리 재생이 끝난 뒤 실행되는 콜백은 **몇 초 전 렌더의 값**을 들고 있다. 그래서 "지금 진짜 값"은 ref에서 읽고, "화면에 그릴 값"은 state로 둔다.

**실제로 이것 때문에 버그가 났었다** — 진행 막대가 `outcomesRef`를 렌더에서 읽어 0%에 얼어 있었다(`근거`: `WrsSessionScreen.test.tsx`의 테스트 주석). 지금은 테스트가 그 자리를 지킨다.

**읽을 때 규칙**: `~Ref`로 끝나면 화면과 무관한 값이다. 화면을 의심할 땐 `useState` 쪽만 본다.

ref 전용(짝 없는) 것들:

| ref | 하는 일 |
|-----|--------|
| `savedRef` | 이번 세션을 이미 저장했나 (중복 저장 방지) |
| `abortRef` | 화면을 떠났나 (떠난 뒤 콜백이 상태를 건드리지 않게) |
| `trialsRef` · `outcomesRef` | 진행 중 문항·결과 (비동기 콜백이 읽음) |

## 6. 한 상태를 여러 곳에서 바꾸는 자리 (지침 §3 세 번째 행)

**`(phase)` 하나가 여러 곳에서 바뀐다.** 이 앱에서 어긋남 위험이 가장 큰 자리다.

```
[시작 버튼]     --설정--> (phase)@연습화면
[소리 재생 완료] --설정--> (phase)@연습화면   ← 비동기
[보기 선택]     --설정--> (phase)@연습화면
[다음 버튼]     --설정--> (phase)@연습화면
[중지 확인]     --설정--> (phase)@연습화면
[재생 실패]     --설정--> (phase)@연습화면   ← 비동기
```

비동기가 둘 섞여 있어서, **화면을 떠난 뒤에 늦게 도착한 콜백**이 `phase`를 되돌려 놓을 수 있다. 그걸 막는 게 `abortRef`다.

```ts
if (abortRef.current) { return; }   // 떠났으면 상태를 건드리지 않는다
```

## 7. 저장소는 상태인가

**아니다 — 그런데 헷갈리기 쉽다.**

| | 상태 (`useState`) | 저장소 (AsyncStorage) |
|---|------------------|---------------------|
| 앱 끄면 | 사라짐 | 남음 |
| 바뀌면 화면이 | 다시 그림 | **안 그림** (직접 읽어야) |

통계 화면이 저장소를 **자기 상태로 복사해 온다**:

```
{저장소 4개} --loadStatsFeed--> (feed)@StatsScreen --그림--> [연습 기록]
```

이건 지침 §4가 경계하는 "서버 데이터를 전역에 복사"와 다르다. **지역 상태이고, 화면을 열 때마다 새로 읽고, 화면을 닫으면 버린다.** 원본은 언제나 저장소다.

`useFocusEffect`로 읽어서, 탭을 떠났다 돌아와도 최신이 된다.

## 8. 단정 금지

- `근거`: 전역 상태 없음(`createContext` 1건이 expo-router 요구), `useMemo` 0건은 grep으로 확인.
- `주의`: `(mode)`는 탭 화면이 들고 있어서 **탭을 떠나면 초기값으로 돌아간다.** 저장소에 남기지 않는다. 의도된 것인지 문서에 명시된 근거는 못 찾았다(`추정`).
- `미검증`: `abortRef`가 모든 늦은 콜백을 막는지 시나리오 테스트는 없다. 코드상 분기만 확인.
