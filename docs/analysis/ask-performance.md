## 2. 목록·대량 — 그릴 게 몇 개인가

지침 §2-3은 "몇 개를 그리나, 가상화하나"를 묻는다. 이 앱의 답:

| 화면의 목록 | 최대 개수 | 가상화 필요? |
|------------|----------|------------|
| 보기 칸 (한 글자·두 글자) | **4개** | 불필요 |
| 링 6 음소 칸 | **6개** | 불필요 |
| 빙고 판 | **9개** | 불필요 |
| 통계 칩 | **6개** | 불필요 |
| 최근 연습 목록 | **8개** (`.slice(0, 8)`) | 불필요 |
| 추이 그래프 점 | **최대 50개** (SVG `<Circle>`) | 아래 참고 |
| 「다른 연습」 줄 | **3개** | 불필요 |

**`FlatList`가 없는 게 맞다.** 지침 §4가 경계하는 "긴 리스트를 가상화 없이 전부 렌더"는 **긴 리스트가 없어서** 해당하지 않는다.

### 상한이 구조적으로 걸려 있다

```ts
export const MAX_MEASURE_SESSIONS = 50;   // 트랙별
export const MAX_LING6_DAYS = 50;
export const MAX_WRS_SESSIONS = 50;
export const MAX_TWO_CHAR_SESSIONS = 50;
```

**저장할 때 자른다.** 1년을 매일 써도 51건째부터는 오래된 것이 버려진다. 그래서 "데이터가 쌓여서 느려지는" 경로가 아예 막혀 있다.

**하나 지켜볼 자리**: 그래프 50점은 SVG 노드가 점 50 + 선 1개다. 지금은 문제없어 보이지만(`추정`), 상한을 올리면 여기부터 확인해야 한다.

## 3. 리렌더 — 무엇이 무엇을 다시 그리나

```
(phase) ⟳ [연습 화면 전체]
```

연습 화면은 `phase`가 바뀔 때마다 통째로 다시 그린다. 문항 하나당 3~4번(`playing` → `choose` → `feedback` → 다음).

**이게 문제인가?** — 위 §2대로 그리는 게 4~9칸이다. **값싼 렌더**다. 지침 §2-1의 "리렌더가 있다고 다 문제는 아니다. 값싼 렌더는 놔둔다"에 해당한다.

### `useCallback`이 101개인데 `memo`가 0개인 건 모순 아닌가

**아니다.** 이 앱의 `useCallback`은 성능용이 아니라 **훅 의존성 배열용**이다.

```ts
useFocusEffect(
  useCallback(() => { reload(); }, [reload]),
);
```

`useCallback`을 안 쓰면 `reload`가 매 렌더 새 함수가 되고, `useFocusEffect`가 매 렌더 다시 돈다 — **성능이 아니라 동작이 깨진다.** 자식이 `memo`가 아니니 참조 안정성은 렌더 절약에 쓰이지 않는다.

→ 지침 §4의 "모든 컴포넌트에 `useCallback` 바르기"와는 다른 이유로 붙어 있다.

## 4. 진짜 무거운 쪽 — 소리

화면이 아니라 여기가 이 앱의 비용 중심이다.

| 자리 | 무엇 |
|------|------|
| `src/audio/amTone.ts` | 오실레이터 2개 + 게인 3개를 **매 시행 새로 만들고 버림** |
| `src/audio/pureTone.ts` | 순음 재생 |
| `ling6Synth.ts` | 링 6 말소리 합성 |
| `wrsTts.ts` | 안드로이드 TTS 호출 |

**AudioContext는 하나를 재사용한다:**

```ts
let sharedContext: AudioContext | null = null;
function getContext(): AudioContext {
  if (!sharedContext) { sharedContext = new AudioContext(); }
  return sharedContext;
}
```

노드(오실레이터·게인)는 재사용할 수 없다 — Web Audio 계열에서 오실레이터는 **한 번 `start`하면 재사용 불가**다. 그래서 매번 만들고, 끝나면 `disconnectAll()`로 끊는다.

**여기서 새는 게 있으면 진짜 성능 문제가 된다**(노드가 안 끊기고 쌓임). 지금 코드는 `onEnded`에서 끊고, `activeCarrier === carrier` 비교로 **이전 시행의 늦은 콜백이 지금 것을 끊지 않게** 막고 있다.

`추정`: 이 부분이 이 앱에서 측정을 붙일 값어치가 가장 큰 자리다. 화면 렌더가 아니라.

## 5. 애니메이션 — 지연 초기화 패턴

`WrsBingoScreen`의 빙고 연출(색종이 16조각):

```ts
const [pieces] = useState(() =>
  Array.from({ length: 16 }, (_, i) => ({
    left: (i * 6.1) % 92,
    ...
    v: new Animated.Value(0),
  })),
);
```

**`useState`에 함수를 넘기는 게 핵심이다.** `useState(만들기())`로 쓰면 매 렌더 16개를 새로 만들고 버린다(값은 첫 번째 것만 쓰이므로 **낭비만** 된다). `useState(() => 만들기())`로 넘기면 **첫 렌더에서 한 번만** 실행된다.

파일에도 그렇게 적혀 있다:

> 지연 초기화 useState가 `Animated.Value`를 한 번만 만드는 표준 방식(`equalizer.tsx`와 같음).

별도 학습 노트가 있다: `docs/animated-value-초기화-노트.md`

**모든 애니메이션이 `useNativeDriver: true`다**(`근거`: 5곳 전부). JS 스레드를 안 거치고 네이티브에서 돌아, 연습 중에 애니메이션이 끊기지 않는다.

## 6. 로드·크기

| 항목 | 상태 |
|------|------|
| 지연 로딩(lazy import) | **없음** — 앱이 작아서 전부 초기에 로드 |
| 큰 라이브러리 | `react-native-audio-api`(오디오), `react-native-svg`(그래프) |
| 이미지 | 링 6 음소 그림(`assets/`) |
| 스플래시 | `AnimatedSplashOverlay`로 가림 |

**탭 4개가 전부 처음에 마운트되는가**가 이 축에서 볼 자리다. `NativeTabs`는 탭을 살려 두는 방식이라(`근거`: `handoff.md`에 "현재 `NativeTabs`는 화면을 계속 살려둬서 자동 갱신 안 됨"), 한 번 연 탭은 메모리에 남는다.

→ 그래서 통계 화면이 `useFocusEffect`로 다시 읽는다. 안 그러면 옛날 데이터가 남는다. **이건 성능 절약(살려 둠)의 대가로 생긴 정확성 문제**이고, 이미 처리돼 있다.

## 7. 저장소 읽기 비용 (2026-08-21 변경)

```
[통계 열기] --예전--> {저장소 1개} 읽기
[통계 열기] --지금--> {저장소 4개} 동시 읽기
```

**왜 4개가 됐나**: 「다른 연습」 3줄이 다른 종목의 최신 1건을 알아야 하는데, AsyncStorage는 **부분 읽기가 안 된다.** 최신 1건을 알려면 그 키 전체를 읽어야 한다.

**얼마나 늘었나 (계산, 측정 아님)**:

| | 값 |
|---|---|
| 레코드 1건 | 요약 숫자 3~7개 ≈ 100~200 바이트 |
| 저장소 1개 | 50건 → 5~10 KB |
| 4개 합 | **수십 KB** |

`추정`: 밀리초 단위. **측정하지 않았다.**

**중요한 건 한 번만 읽는다는 것**이다. 칩을 눌러 종목을 바꿔도 다시 안 읽는다 — 이미 메모리에 있는 봉투에서 골라 그린다.

## 8. 성능이 아니라 **레이아웃**이었던 버그 (2026-08-21)

성능 축을 볼 때 헷갈리기 쉬운 실제 사례라 여기 적는다.

통계 화면 칩이 화면을 다 잡아먹었다. 원인은 렌더 비용이 아니라 **RN `ScrollView`의 기본 스타일**이었다.

```
horizontal ScrollView 기본 스타일 = { flexGrow: 1, flexShrink: 1, flexDirection: 'row' }
```

세로 부모 안에서 `flexGrow: 1`이라 남은 세로 공간을 다 차지했고, `contentContainer`의 기본 `alignItems: stretch` 때문에 칩이 그 높이만큼 늘어났다.

```ts
chipScroll: { flexGrow: 0, flexShrink: 0 },
chipRow: { alignItems: "center", ... },
```

**교훈**: 화면이 이상하면 리렌더부터 의심하지 말 것. 지침 §0 "이유 2"(측정 없이 추측하면 엉뚱한 데를 고친다)의 실물 사례다.
