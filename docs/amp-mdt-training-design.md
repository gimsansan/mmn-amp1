# AMP/MDT · 청능 훈련 설계 (확정 기록)

> **상태**: 대화로 합의된 제품·자극·엔진 방향 기록 (2026-08).  
> **구현 순서**: **② 주파수 변별 먼저** → **① AM/포락선은 CI 중심 추가 옵션**(스펙 초안만 확정, 일정은 후순위).  
> **관련 스택**: `docs/dev-client-setup-context.md` §1 오디오 (`react-native-audio-api` `^0.13.2`).

---

## 0. 한 줄 요약

앱은 병원식 검사가 아니라 **웰니스·훈련**.  
**CI → ① 떨림(포락선) 핵심 / 비CI → ② 주파수 변별 중심**. ②는 공통 콘텐츠로 그대로 진행.  
①은 같은 엔진·계단식 틀을 재활용하는 **추가 옵션**(비CI에서 불가 아님, **후순위**).  
훈련이 실제 청취를 개선한다는 주장은 **검증 대상**(가정 금지).

---

## 1. 제품 프레이밍 (용어)

| 쓸 것 | 쓰지 말 것(진단적 주장) |
|--------|-------------------------|
| 웰니스, 훈련, 연습, 내부 난이도 조정 | 진단, 스크리닝, 재활·환자(병원 대체 암시), “역치 확정” |

- 병원이 이미 **매핑(MAP), 말지각, 음장 청력** 등으로 정기 평가함.
- AMP/MDT는 연구·세부 심리음향에 가깝고 **모든 병원 정기 항목은 아님**.
- 앱의 존재 이유: 그 사이의 **반복 훈련**.  
  앱 안 MDT(①을 넣을 때)는 **진단 대체**가 아니라 **훈련 난이도를 개인에 맞추는 내부 조정**.

**테스트 vs 훈련**
- 테스트: 실력 측정만. 자주 해도 그 자체로 늘지 않음.
- 훈련: 한계 근처 난이도를 **계속 조이며 반복**.

---

## 2. MDT가 재는 것 (①의 과학 근거)

- **MDT** (Modulation Detection Threshold): 소리 크기 출렁임(시간적 **포락선**)을 얼마나 얕게까지 감지하는가.
- **AMP** (Amplitude Modulation): 그 출렁임을 만드는 자극 방식.
- CI 사용자는 세밀한 음높이보다 **크기 변화**로 말을 듣는 경향 → ①의 1순위 근거.
- **청력역치(얼마나 작은 소리까지 들리냐)** 와는 다름. 소리는 충분히 들리게 두고 **떨림의 얕음**을 본다.

**대상**
- CI: ① 핵심 근거·우선 대상.
- 비CI(보청기·고령 난청 등): ① **배제하지 않음**. 다만 제품 우선순위상 **후순위**.

---

## 3. 두 트랙

①과 ②는 자극·측정 능력이 다른 **별개 트랙**(2-down-1-up 계단식 틀만 공유).

| 대상 | 1순위 | 보조 / 후순위 |
|------|-------|----------------|
| **CI** | **① 떨림(포락선)** | ② 주파수 변별 (더 어렵지만 가능·무관 아님) |
| **비CI** | **② 주파수 변별** | ①은 후순위 옵션; 필요 시 소음 속 말 연습 등 |

- **②는 공통 콘텐츠**(비CI 전용 아님). 비CI에 상대적으로 더 잘 맞음.
- **② = 원래 청능 콘텐츠 → 그대로 진행.**
- **① = 같은 엔진·계단식으로 나중에 얹을 카드.** 지금 전부 구현할 필요 없음.

**효과 주장**: ①·② 모두 “실제 청취 능력 개선”은 **검증 대상**. 특히 CI에서 ②, 비CI 전반 효과는 근거가 더 약할 수 있음 → 청각 전문가·근거 확인.

## 4. 오디오 엔진 (확정)

- 엔진: **`react-native-audio-api` `^0.13.2`** (Web Audio 호환 그래프).
- Android: **Oboe I/O 위**에서 동작. “Oboe 없이”가 아님. Oboe를 JS 친화 그래프로 **감싸 쓰는** 구조.
- RN에는 브라우저 네이티브 Web Audio 없음. 문서의 “Web Audio” = 이 라이브러리.
- **SoundPool 사용 안 함** — 짧은 효과음용. AM 깊이 실시간 합성에 부적합.

### ① AM 합성 (스펙 초안 — 구현은 후순위)

표준 패턴: carrier → Gain(출력) → destination.  
modulator(LFO) → depth Gain → **출력 Gain의 `gain` AudioParam** (`connect` 지원, 공식 문서 LFO 예제).

- 출력 `gain.value = A` 가 **DC 오프셋(+1 역할)**.
- 실제 gain ≈ `A + A·m·sin` → **진짜 AM**.
- 오프셋 없으면 gain이 0 중심으로 흔들려 **링 모듈레이션(DSB-SC)** → MDT가 아님.
- 조건: **오프셋 유지 + `m ≤ 1`**(깊이 ≤ 오프셋) → gain ≥ 0, 과변조·위상 반전 방지.
- `m` (0~1), dB = **20·log₁₀ m** (m=1 → 0 dB가 가장 쉬움). 계단식이 조절하는 값 = m(또는 dB).
- `f_m` 예: 4 / 8 / 16 Hz — 사이드밴드가 반송파 임계대역에 묻혀 **순수 시간 포락선** 단서에 가깝게(CI 취지에 맞음).

### 타당성 안전장치 (① 구현 시 필수)

1. **온셋·오프셋 게이팅(ramp)** — 급격한 끊김 → 클릭 단서. 시작·끝 20~50 ms 상승·하강(레이즈드 코사인 등).
2. **구간 간 RMS 등화 또는 레벨 로빙** — 변조로 파워가 커져 “더 큰 소리”로 맞추는 교란 차단.
3. **과변조 방지 `m ≤ 1`** (+ 오프셋 구조).

### UX·시각 (공통 원칙)

- **시각을 변조 깊이(난이도)에 연동하지 않음** — 귀가 아니라 눈으로 통과(시각 누수).
- 별빛 등 게이지: **진행**과 **정오답**을 정의로 분리. 게이지가 깊이/난이도를 암시하면 안 됨. n-AFC 시행별 정오답 피드백은 허용 가능.
- 홀드-릴리스(0.3초)보다 **큰 탭 + 확인**이 고령자 접근성에 나을 수 있음 → 사용성 테스트로 결정.
- 권장 과제형: 사후 선택 n-AFC, 자극 종료 전 입력 비활성, 타임아웃 제거, 반응시간/정오답 분리 판정.
- 휴식 트리거: “같은 깊이 연속 오답”은 계단식과 상충하기 쉬움 → **시행 수·경과 시간** 기준.

## 5. 계단식 규칙

| 항목 | ① AM 깊이 (MDT) — 후순위 옵션 | ② 주파수 변별 (JND) — 우선 구현 |
|------|-------------------------------|----------------------------------|
| 측정 | 최소 감지 변조 깊이 | 최소 구별 주파수 차 |
| 적응 변수 | m → dB (20·log₁₀ m) | 주파수 차 → **cent** |
| 자극 | 반송파(예: 1 kHz) + 정현 AM | 순음 비교(기준 vs 변화) |
| 과제 | n-AFC (예: “떨리는 것”) | n-AFC (예: “다른 음”) |
| 수렴 | 2-down-1-up (≈70.7%) | 동일 구조 |
| 스텝 | **제안** 6 dB → 반전 2회 후 2 dB (파일럿 튜닝) | ±10 cent (HarmoniTune) |
| 범위 | 시작 m=1(0 dB), 상한 0 dB / 하한 엔진 분해능 | **10~150 cent** (확정) |
| 종료 | 반전 6~8회 후 마지막 반전 평균(관례 제안) | 동일 관례 가능 |
| 출처 | 신규(표준 관례 기반 제안) | HarmoniTune 피치 계단식 재사용 |

- 주파수 단위는 **cent로 통일**(지각·② 재사용). RFP의 “10~50 Hz”(440 Hz 기준 대략 39~186 cent)는 상한만 150 cent에 맞춤.
- HarmoniTune ② 참고: A4 440 Hz, 2연속 정답 −10 / 오답 +10, 10~150 cent.
