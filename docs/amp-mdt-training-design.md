## 0. 한 줄 요약

앱은 병원식 검사가 아니라 **웰니스·훈련**.  
**CI → ① 떨림(포락선) 핵심 / 비CI → ② 주파수 변별 중심**. ②는 공통 콘텐츠로 그대로 진행.  
①은 같은 엔진·계단식 틀을 재활용하는 **추가 옵션**(비CI에서 불가 아님, **후순위**).  
훈련이 실제 청취를 개선한다는 주장은 **검증 대상**(가정 금지).

## 1. 제품 프레이밍 (용어)

| 쓸 것 | 쓰지 말 것(진단적 주장) |
|--------|-------------------------|
| 웰니스, 훈련, 연습, 내부 난이도 조정 | 진단, 스크리닝, 재활·환자(병원 대체 암시), “역치 확정” |

- 병원이 이미 **매핑(MAP), 말지각, 음장 청력** 등으로 정기 평가함.
- AMP/MDT는 연구·세부 심리음향에 가깝고 **모든 병원 정기 항목은 아님**.
- 앱의 존재 이유: 그 사이의 **반복 훈련**.  
  앱 안 MDT(①을 넣을 때)는 **진단 대체**가 아니라 **훈련 난이도를 개인에 맞추는 내부 조정**.

**테스트 vs 훈련**
- 테스트: 실력 측정만. 자주 해도 그 자체로 늘지 않음.
- 훈련: 한계 근처 난이도를 **계속 조이며 반복**.

## 2. MDT가 재는 것 (①의 과학 근거)

- **MDT** (Modulation Detection Threshold): 소리 크기 출렁임(시간적 **포락선**)을 얼마나 얕게까지 감지하는가.
- **AMP** (Amplitude Modulation): 그 출렁임을 만드는 자극 방식.
- CI 사용자는 세밀한 음높이보다 **크기 변화**로 말을 듣는 경향 → ①의 1순위 근거.
- **청력역치(얼마나 작은 소리까지 들리냐)** 와는 다름. 소리는 충분히 들리게 두고 **떨림의 얕음**을 본다.

**대상**
- CI: ① 핵심 근거·우선 대상.
- 비CI(보청기·고령 난청 등): ① **배제하지 않음**. 다만 제품 우선순위상 **후순위**.

## 3. 두 트랙

①과 ②는 자극·측정 능력이 다른 **별개 트랙**(2-down-1-up 계단식 틀만 공유).

| 대상 | 1순위 | 보조 / 후순위 |
|------|-------|----------------|
| **CI** | **① 떨림(포락선)** | ② 주파수 변별 (더 어렵지만 가능·무관 아님) |
| **비CI** | **② 주파수 변별** | ①은 후순위 옵션; 필요 시 소음 속 말 연습 등 |

- **②는 공통 콘텐츠**(비CI 전용 아님). 비CI에 상대적으로 더 잘 맞음.
- **② = 원래 청능 콘텐츠 → 그대로 진행.**
- **① = 같은 엔진·계단식으로 나중에 얹을 카드.** 지금 전부 구현할 필요 없음.

**효과 주장**: ①·② 모두 “실제 청취 능력 개선”은 **검증 대상**. 특히 CI에서 ②, 비CI 전반 효과는 근거가 더 약할 수 있음 → 청각 전문가·근거 확인.  
상세 구분·한계: 아래 **§4**.

### 3.1 병합 후 3트랙 (제품 카드 · HarmoniTune 병합)

> 과학 트랙은 여전히 **② 음고(주파수/피치) 변별**·**① 포락선(AM)** 2계열. 병합으로 제품 「연습」탭이 **카드 3개**가 됐다(정본: `docs/merge-plan-harmonitune.md` §0). 「2AFC/3AFC」는 관례 약칭 → **UI 문구로 쓰지 않는다**(쉬운 한글만).

| 카드 | 과제(쉬운 말) | 심리음향 | 과학 계열 | 출처(코드) |
|------|----------------|----------|-----------|-----------|
| 높낮이 비교 | A→B 듣고 더 높/낮 (2택) | 2AFC | ② 음고 변별 | HarmoniTune `pitch2afc/` |
| 다른 음 찾기 | 3구간 중 다른 음 (3택) | 3AFC (odd-one-out) | ② 음고 변별 | mnn ② `freq*` |
| 떨림 찾기 | 크기 출렁임(AM) 감지 | 3AFC | ① 포락선 | mnn ① `am*` |

- 「높낮이 비교」·「다른 음 찾기」는 **둘 다 ② 계열**. **과제·자극은 다름**(2AFC A→B vs 3AFC odd-one-out) → 트랙별 파일은 유지(merge-plan §2-4).
- **계단식 파라미터는 2026-08-13 통일**(「다른 음 찾기」=「높낮이 비교」). **정본은 코드**: `freq/freqStaircase.ts` · `pitch2afc/constants.ts`. 문서에 시작·범위·스텝 숫자를 복사하지 않음.
- `추정`: 세 카드를 한 앱에 묶었을 때의 세션 길이·피로·이탈은 실기기 미확인(merge-plan §7).

## 4. 과학적 타당성·한계 (구현 전 기록)

> **목적**: 코드를 짜기 전에, “무엇을 재·연습한다고 말하는지”와 “무엇을 아직 주장하면 안 되는지”를 문서에 고정한다.  
> **성격**: 제품·심리음향 **관례·합의** 정리. **논문 DOI·임상 근거 목록은 아직 없음** → 청각 전문가 검토 후 보강.  
> **표기**: `관례` = 분야 표준에 가깝다고 보는 것 · `가설` = 전이·효과 가정 · `미검증` = 이 앱에서 증명되지 않음.

### 4.1 세 가지를 섞지 말 것

| 종류 | 질문 | 이 앱에서의 상태 |
|------|------|------------------|
| **구성(무엇을 다루는가)** | 과제가 주파수 차 / AM 깊이를 겨냥하는가 | ②·① 설계 의도와 일치 (**관례**) |
| **방법(어떻게 측정·적응하는가)** | n-AFC + 2-down-1-up + 교란 차단이 적절한가 | 심리음향 **관례**에 맞춤. 앱 파라미터(cent 범위 등)는 HarmoniTune·합의값 |
| **전이·효과(실생활이 나아지는가)** | 연습이 말소리·일상 청취를 개선하는가 | **미검증**. 카피·스토어에 쓰지 않음 |

웰니스·훈련 프레이밍(§1)은 위 표의 **전이를 주장하지 않기** 위한 제품 결정이기도 하다.

### 4.2 ② 주파수 변별 (우선 구현) — 왜 이 과제인가

**구성 (관례)**  
- 순음(또는 단순 톤)의 **주파수 차 구별**은 고전 심리음향의 **주파수/피치 변별(JND)** 과제와 같은 계열이다.  
- 단위 **cent** = 로그 주파수 비(1200 cent = 1 옥타브). Hz 고정 스텝보다 **지각 스케일에 가깝게** 난이도를 다루기 쉬워, 이 앱도 cent로 통일한다.  
- n-AFC에서 “다른 음”을 고르게 하면, 적응 변수는 **주파수 차(Δf → cent)** 이다. 청력역치(얼마나 작은 소리)와는 별개다.

**대상·우선순위 근거 (관례 + 가설)**  
- 말소리·음악에서 **기본주파수(F0)·배음·포먼트 위치** 등 “높낮이·스펙트럼 자리” 단서가 쓰인다 → 주파수 변별을 **연습 후보**로 두는 이유(**가설** 쪽 연결, 전이 증명 아님).  
- 보청기·고령 난청 등에서는 주파수 선택성·변별이 어려워지는 경우가 많다는 임상·연구 맥락이 있어, 제품상 **비CI에 ②를 상대적으로 더 맞춤**(**관례적 동기**, 이 앱 효과 데이터 아님).  
- CI는 전극·채널 한계로 **세밀한 음높이**가 어렵고 포락선 의존이 큰 편 → ②는 CI에서 **1순위 근거가 약함**. “무관”이 아니라 **후순위·가능**으로 둔다(§2·§3).

**방법 (관례)**  
- **2-down-1-up**: 연속 2정 → 더 어렵게, 1오 → 더 쉽게. 정답률 약 **70.7%** 지점 근처로 모이는 **적응 계단식**의 전형( Levitt류 adaptive procedure **관례** ).  
- 훈련 모드에서는 같은 규칙을 **한계 근처 반복 연습**에 쓴다. 반전 평균으로 “임상 역치 확정”을 앱 결과로 내세우지 않는다(§1).  
- 파라미터 **정본은 코드**. 「다른 음 찾기」=`freq/freqStaircase.ts`, 「높낮이 비교」=`pitch2afc/constants.ts`(2026-08-13 두 트랙 계단식 통일). 임상 표준 프로토콜 인용값이 아님. `미검증`: 파일럿 청취 전 설계 목적값.

**구성이 무너지지 않게 (② 구현 시)**  
- 레벨·클릭·길이 차이로 “다른 음”을 맞히면 주파수 변별이 아님 → 온셋 램핑, 구간 레벨 맞춤 등(① 안전장치와 같은 취지).  
- **시각을 난이도(cent)에 연동하지 않음**(§5 UX).

### 4.3 ① AM / MDT (후순위 옵션) — 요약

- **구성**: 시간적 **포락선(크기 출렁임)** 감지. CI 말지각과의 연결은 §2 (**관례적 동기**).  
- **방법**: 진짜 AM(오프셋 유지), `m ≤ 1`, 게이팅·RMS/레벨 로빙(§5 안전장치) — 링 모듈레이션·클릭·크기 단서면 MDT가 아님.  
- **전이·효과**: 역시 **미검증**. 앱에 넣을 때도 진단·재활 대체 문구 금지.

### ① AM 합성 (스펙 초안 — 구현은 후순위)

표준 패턴: carrier → Gain(출력) → destination.  
modulator(LFO) → depth Gain → **출력 Gain의 `gain` AudioParam** (`connect` 지원, 공식 문서 LFO 예제).

- 출력 `gain.value = A` 가 **DC 오프셋(+1 역할)**.
- 실제 gain ≈ `A + A·m·sin` → **진짜 AM**.
- 오프셋 없으면 gain이 0 중심으로 흔들려 **링 모듈레이션(DSB-SC)** → MDT가 아님.
- 조건: **오프셋 유지 + `m ≤ 1`**(깊이 ≤ 오프셋) → gain ≥ 0, 과변조·위상 반전 방지.
- `m` (0~1), dB = **20·log₁₀ m** (m=1 → 0 dB가 가장 쉬움). 계단식이 조절하는 값 = m(또는 dB).
- `f_m` 예: 4 / 8 / 16 Hz — 사이드밴드가 반송파 임계대역에 묻혀 **순수 시간 포락선** 단서에 가깝게(CI 취지에 맞음).

### 타당성 안전장치 (① 구현 시 필수)

1. **온셋·오프셋 게이팅(ramp)** — 급격한 끊김 → 클릭 단서. 시작·끝 20~50 ms 상승·하강(레이즈드 코사인 등).
2. **구간 간 RMS 등화 또는 레벨 로빙** — 변조로 파워가 커져 “더 큰 소리”로 맞추는 교란 차단.
3. **과변조 방지 `m ≤ 1`** (+ 오프셋 구조).

### UX·시각 (공통 원칙)

- **시각을 변조 깊이·주파수 차(난이도)에 연동하지 않음** — 귀가 아니라 눈으로 통과(시각 누수).
- 별빛 등 게이지: **진행**과 **정오답**을 정의로 분리. 게이지가 깊이/난이도를 암시하면 안 됨. n-AFC 시행별 정오답 피드백은 허용 가능.
- 홀드-릴리스(0.3초)보다 **큰 탭 + 확인**이 고령자 접근성에 나을 수 있음 → 사용성 테스트로 결정.
- 권장 과제형: 사후 선택 n-AFC, 자극 종료 전 입력 비활성, 타임아웃 제거, 반응시간/정오답 분리 판정.
- 휴식 트리거: “같은 깊이 연속 오답”은 계단식과 상충하기 쉬움 → **시행 수·경과 시간** 기준.

## 6. 계단식 규칙

> **정본은 코드 상수.** 시작·범위·스텝·반전 목표 숫자는 여기에 복사하지 않는다(복사하면 코드와 어긋남).  
> `freq/freqStaircase.ts` · `am/amStaircase.ts` · `pitch2afc/constants.ts` · `sessionMode.ts`.  
> `미검증`: 코드의 현재 값은 설계 목적값, 실측 아님.

| 항목 | ① AM 깊이 (MDT) — 「떨림 찾기」 | ② 주파수 변별 — 「다른 음 찾기」·「높낮이 비교」 |
|------|-------------------------------|----------------------------------|
| 측정 | 최소 감지 변조 깊이 | 최소 구별 주파수 차 |
| 적응 변수 | m → dB (20·log₁₀ m) | 주파수 차 → **cent** |
| 자극 | 반송파 + 정현 AM | 순음 비교(기준 vs 변화) |
| 과제 | 3AFC (「떨리는 것」) | 3AFC 다른 음 / 2AFC 높낮이 |
| 수렴 | 2-down-1-up (≈70.7%) | 동일 구조 |
| 스텝 | 가변(반전이 쌓이면 폭이 좁아짐) | 가변. **freq = pitch2** |
| 범위·시작 | 쉬운 쪽(큰 깊이)에서 시작, 하한 있음 | 쉬운 쪽(큰 Δ)에서 시작. **freq = pitch2** |
| 종료 | 귀풀기: 한도 없음(직접 종료). 연습: 전환 6 | 동일 |
| 정본 | `am/amStaircase.ts` | `freq/freqStaircase.ts` · `pitch2afc/constants.ts` |

**귀풀기 / 연습** (`sessionMode.ts`)  
- 스텝 정책은 모드로 쪼개지 않음. **가변 하나**.  
- 귀풀기: 전환·시행 한도 없음, 직접 종료. 기록은 남기되 **통계·추세 제외**.  
- 연습: **전환 6** 후 종료. 기록 + **통계 포함**. idle 기본=귀풀기. 숫자는 코드 정본.  
- pitch2 `ASSESSMENT`는 **별도 평가 프로토콜 상수**. 현재 세 화면 토글은 `targetReversalsFor`.

- 주파수 단위는 **cent로 통일**(①은 dB라 제외).
- `주의`: am 하한을 올려도 바닥 반전 몰림은 완화만, 근본 해결 아님.

### 6.1 「높낮이 비교」(pitch2) — 자극만 다름

계단식 숫자는 §6 ②와 같고 **정본은** `pitch2afc/constants.ts`의 `STAIRCASE`. 여기는 과제·자극.

- 과제: A→B 듣고 더 낮/높 (2택). 기준음·길이·간격은 같은 파일 `AUDIO`.
- **시작값 정정(2026-08-12)**: HH 문서의 작은 시작값은 폐기. 코드 `STAIRCASE.INITIAL_CENTS`가 정본(초심자가 첫 문제부터 틀리던 값에서 올림).
- `추정`: 상한·가변 스텝·톤 길이의 적정성은 파일럿 미검증. 실기기 청취 미확인.
