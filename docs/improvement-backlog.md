### P1-6. 저장 키가 4개로 나뉘어 있음 — 하나로 합칠 것인가

> 🚫 **2026-08-21 안 하기로 함.** 코드 확인 결과 **합치는 것이 중립이 아니라 손해**. 필요가 생기면 저장소가 아니라 **읽기 쪽 집계 레이어**를 추가한다.

**현재 상태 — 6트랙 / 4상자**

| 키 | 담는 것 | 쓰기 방식 | 상한 |
|---|---|---|---|
| `training.sessionHistory.v1` | **freq + am + pitch2 (3트랙)** | append | 트랙별 50 |
| `training.ling6Daily.v1` | 링 6 | **날짜 upsert**(그날 1건 덮어쓰기) | 50일 |
| `training.wrsSessions.v1` | 한 글자 | append | 50 |
| `training.twoCharSessions.v1` | 두 글자 | append | 50 |

**① 저장 구조와 표시 구조는 무관하다 — 이 앱이 이미 증명함**

`sessionStore.ts`는 freq·am·pitch2를 **한 배열**에 `track` 필드로 섞어 넣고, 화면에서 필터링해 **탭별로 따로** 보여준다. 즉 한 상자에 있어도 화면은 나뉜다. 합쳐도 화면은 안 바뀌고, 「한눈에 보기」를 원하면 **홈 요약 화면을 만드는 별개의 일**이다.

**② 합치면 코드가 준다 → 사실이 아님**

`ling6Store`는 **날짜 upsert**다(`그날 점검 1건으로 덮어쓴다 … 같은 날짜를 치환하므로 가로축이 세션 횟수로 늘어나지 않는다`). 나머지 셋은 **세션 append**다. **수명 주기가 다르다.** 한 배열에 넣으면 쓰기 경로에서 「덮어쓰기냐 붙이기냐」를 매번 분기해야 하고, 상한도 지금처럼 트랙별로 따로 세야 한다. 코드가 줄지 않고 **는다**.
`ling6Store.ts:11` 주석이 이미 같은 이유를 적어두었다 — `일자 1레코드. 기존 세션 append 키와 섞지 않는다.`

**③ 마이그레이션은 일회성이 아니라 영구 부채**

구버전 앱을 쓰던 기기가 언제 업데이트할지 알 수 없으므로 **옛 키 4개를 읽는 경로를 지울 수 없다.** 「한 번 옮기면 끝」이 아니다.

**④ 원래 목적 두 가지 모두 저장소 변경이 불필요**

1. **홈 요약 화면** — 4번 읽어 `Promise.all`로 합치면 끝. 작은 JSON 4개라 체감 지연 없음(`추정`, 실측 안 함).
2. **문항 로그 내보내기** — 마찬가지로 읽어서 합치는 함수 하나.

→ `collectAllRecords()` 같은 **집계 모듈 1개**면 된다. 저장소 무변경 · 마이그레이션 0 · 기존 화면 영향 0.

- **관련 경로**: `src/training/sessionStore.ts` · `src/training/ling6/ling6Store.ts` · `src/training/wrs/wrsStore.ts` · `src/training/wrs/twoCharStore.ts`
- **연관 항목**: P2-7(기록 화면 내보내기 공백) · P2-8(홈 화면)
